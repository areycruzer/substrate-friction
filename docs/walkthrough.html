STEP 5 / THE AGENT ASKS FIRST

An AI agent consults the seatbelt — and backs off.

Over MCP — the protocol Claude Code, Cursor and OpenHands speak — a real client session asks the gate before trusting its own map. The decision rule here is a scripted, disclosed policy; the transport, the server and the verdict are real — the puppet is scripted, the refusal is real, and it is the same tool a live agent would call:

scripts/abstention_demo.py — MCP sessionreceipt · verbatim · click
# The abstention loop, demonstrated over MCP

Generated by `scripts/abstention_demo.py` — a real MCP client session against `friction-mcp` over stdio, the same protocol coding agents (Claude Code, Cursor, OpenHands) speak.

**Disclosure first:** the client's decision rule is a scripted policy, not an LLM. What is real: the MCP transport, the server, the measured verdict, and the behavioural branch. The demonstrated claim is exactly this and no more: *an external, measured signal can drive an agent-protocol abstention decision* — the piece the 2026 abstention literature (AgentAbstain: best of 17 frontier models at 59.5% paired accuracy; capability does not scale it away) identifies as missing from model-internal confidence.

## Transcript (verbatim)

```
[client] connected over stdio; server tools: ['gate_check', 'gate_explain', 'graph_query']
[agent]  task: 'change src touching the ORM; run affected tests'
[agent]  policy (scripted, disclosed): ask gate_check before trusting any graph-selected subset
[gate]   decision=RUN_FULL recall=0.5455 n=44 bar=0.95
[agent]  ABSTAIN from subset selection -> running the FULL suite (the external signal overrode the graph walk)
[gate]   evidence replay: django__django-10097 — graph_complete=True, selected 0 of 370 guarding tests
[agent]  behaviour taken: full-suite
```

Running it against a hypothetical certified graph (recall >= 0.95) takes the other branch — the policy is two lines, which is the point: once the signal exists, consuming it is trivial. Wiring the same tool into an LLM-driven agent and measuring behaviour change on SWE-bench instances is `docs/future-work.md` material and is not claimed here.
